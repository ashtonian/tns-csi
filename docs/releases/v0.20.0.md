## v0.20.0 — Reliability and storage safety

This release includes the reliability overhaul in [#287](https://github.com/fenio/tns-csi/pull/287), plus the pinned K3S E2E bootstrap in [#288](https://github.com/fenio/tns-csi/pull/288) and test dependency updates in [#289](https://github.com/fenio/tns-csi/pull/289).

### Highlights

- **Safer NFS/SMB unstage:** mount detection reads the kernel mount table and fails closed on lookup errors. Staging cleanup removes only empty directories, never recursively deletes share contents.
- **Safer volume deletion:** unreadable ownership/retain properties stop deletion. iSCSI and NVMe-oF presentation objects are removed before the ZVOL, with identity checks and per-object progress to protect other volumes when recorded IDs are reused.
- **Ownership recorded at creation:** new datasets, ZVOLs, and regular snapshot clones receive ownership metadata in the create/clone request. Retries recover missing presentation metadata.
- **Correct NVMe device identification:** namespace devices, health checks, and rescan controllers are resolved through sysfs rather than guessed from controller numbers, including native NVMe multipath layouts.
- **Safer API retries:** non-idempotent requests are not automatically replayed after a lost response; the client reports an uncertain outcome for reconciliation on retry.
- **Bounded command execution and shutdown:** command output waits are bounded, and SIGTERM drains CSI RPCs for up to 25 seconds before forcing gRPC shutdown.
- **Less API traffic:** exact dataset/resource lookups, server-side filters, and a short-lived dashboard query cache reduce blanket listings.
- **Stronger validation:** race/shuffle unit tests, strict CSI sanity results, coverage and lint-suppression ratchets, vulnerability scanning, and pinned CI tools.

### Upgrade notes

- **TrueNAS SCALE 25.10+ remains required.** Creation-time ownership metadata uses its dataset API fields.
- `DeleteVolume` now returns `Unavailable` when ownership properties cannot be read, instead of risking deletion of retained storage. Check API connectivity and allow the provisioner to retry.
- An existing dataset at a volume ID without `tns-csi:managed_by=tns-csi` now returns `FailedPrecondition`, rather than being silently reported as deleted. Only after confirming that the dataset belongs to this driver, use the recovery procedure in [Deployment troubleshooting](../DEPLOYMENT.md#troubleshooting). Do not mark unrelated datasets as driver-owned.
- The chart passes the API key through `TNS_API_KEY`, not `--api-key`, keeping it out of command-line arguments. Custom manifests using the flag remain supported. Pair this chart with the matching driver, not an older image that lacks environment-variable support.
- Storage metadata remains schema v1; no schema migration is introduced.
- Detached send/receive snapshot restores still rely on a post-create ownership-property write.

Native multipath device-resolution fixes are included, but two-path failover and upgrade scenarios require separate validation; single-path E2E results are not a claim of fully validated multipath failover support.
